# workflow · 对话流程模板

SKILL.md 主流程的话术与节奏由本文档承载——它是 agent 在用户对话里实际"说什么"的剧本。

## 三个 🛑 检查点的话术模板

### 🛑 (a) iCloud 状态

extract_photos.py 跑完后，**只在** `optimized + cloud_only > 0` 时弹出：

```
📷 我扫描了你的相册：

  · 总数：120 张
  · 本地可用：98 张  ✓
  · 已优化（缩略图本地）：15 张  → 可触发完整下载
  · 仅云端：7 张                  → 默认会跳过

要怎么处理云端的 22 张？
  1. 全部触发下载（约 X 分钟，取决于带宽）
  2. 只用本地的 98 张，跳过其它

回复 1 或 2。
```

**不要静默选**——下载几十张照片可能耗 5-30 分钟，用户必须知情。

### 🛑 (b) 行程聚类

cluster.py 跑完后，**总是**展示概览给用户：

```
📅 我把这次旅行分成了这样（共 N 天，M 张照片）：

Day 1 · 2024-03-01
  → 国際通り（10:23-13:45，12 张）
  → 首里城公園（14:30-17:10，16 张）

Day 2 · 2024-03-02
  → 美ら海水族館（09:15-12:40，22 张）
  → 古宇利島（14:00-18:30，13 张）

...

这个划分对吗？需要：
  · 合并某两个相邻地点（"把 Day 1 的两站合并"）
  · 拆分某个地点（"古宇利島下午 16:00 之后是另一个地方"）
  · 调整某天范围（"Day 2 的最后 3 张其实是第二天凌晨拍的"）
  · 没问题，继续 → 回复 ok
```

聚类错了**晚改比早改贵 100 倍**——叙述都按错的地点写完之后，重头来不只是改 JSON，还要重写。

### 🛑 (c) HTML 输出体积

build_diary.py 跑完后，**总是**报告体积；体积超过 200 MB 时**自动建议**relative：

```
✓ 已生成：output/trip.diary.html（48 MB，base64 内嵌 100 张照片）

可以双击打开，地图、灯箱、键盘 ←→ Esc 都已就绪。

要不要我用浏览器打开验证一下？  open output/trip.diary.html
```

体积大时：

```
⚠ HTML 体积 267 MB 超过 200 MB 阈值。
  · 浏览器仍可打开，但加载会慢（10-30 秒）
  · 微信/邮件附件会被拒收

建议改用相对路径模式（约 1 MB HTML + 100 MB 照片目录）：
  python3 scripts/build_diary.py ... --embed-photos relative

要切换吗？
```

## 问问题清单（开工前 / 模糊任务时）

需求不明时**一次性问完**，不要边问边做。模板：

```
开工前我想确认几件事：

1. 输入源：本地文件夹 / Photos.app 相册 / 日期范围？
2. 旅行的大致主题或感觉？（用一句话描述，会帮我起标题；不想说就跳过）
3. 叙述语言：中文（默认）/ 英文 / 其他？
4. 输出位置：默认在项目目录 output/，要换地方吗？
5. 体积偏好：默认 base64 单文件方便分享，还是 relative 模式？

逐条回答即可。不确定就写"默认"。
```

## 用户拒绝回答时的 fallback

用户说「直接做」「不要问了」「你看着办」时——**尊重节奏**，但要求：

1. 用 best judgment 选默认值
2. 在最终交付时**明确标注 assumption**，让用户知道改在哪里：

```
按你「直接做」的要求，我用了这些默认：
  · 跳过云端照片（7 张）
  · 标题用：「冲绳七日，珊瑚礁与春风」（基于地名 + 季节推断）
  · 输出到 output/trip.diary.html，base64 模式

要改任何一个，告诉我。
```

## 节奏原则

- 一次只问一组问题，等用户答完再问下一组
- 一次只跑一个长流程脚本，跑完报告进度再继续
- 🛑 检查点真的"等"——不要说完检查点的话立刻开始下一步
- 进度反馈不需要每张照片一句——按 10% / 25% / 50% / 75% / 100% 报就够了
